# 查無此名就靜默 return 的 API 是假機制的溫床

> 「從程式碼看,一個查無此名就靜默 return 的音效呼叫,和一個真的會發出聲音的系統長得一模一樣。」

引擎裡大量「名字 → 資源」的查找,在查不到時安靜地什麼都不做。這代表你可以寫出一個**程式碼路徑完全正確、測試全綠、但玩家永遠感受不到**的機制。

模型絕對推不出這件事,因為從程式碼看,`play_sound("pick_up")` 和一個真的會發出聲音的系統長得一模一樣。

## 規則

- **任何「名字 → 資源」的查找,都要有一條測試把整張表掃過去確認檔案存在。** 音效、材質、貼圖、動畫剪輯、場景路徑,全部適用。
- 這條測試要綁在**表**上,不是綁在個別呼叫點上 —— 新增一個名字就自動被涵蓋。
- 資源查找失敗如果能改成拋錯,就改成拋錯;不能改的才用測試補。
- **存在性測試只走到一半,另一半是數實際觸發。** 讓播放器累計每個名字被呼叫幾次,跑完一整場之後印出「這一場從來沒觸發過的」清單。檔案存在證明**資產**在,觸發計數證明**程式路徑**在 —— 一個音效可以檔案存在、載得進來、而且永遠不會被呼叫,而那在玩家耳裡跟檔案不見是同一件事。
- **清單裡的每一項都要能解釋。** 「這場沒有 UI 互動所以沒有點擊音」是合理的;「這場贏了但勝利音是 0」不是。不能解釋的就是 bug。

## 案例

**武技做完了,玩家「完全沒特別看」(深坑公會)**

武技的觸發時機與數值做到完全正確,測試全綠。使用者的回饋是「我完全沒特別看」—— 呈現層沒做,份量等於零。

**音效的存在性測試(commit `c52b03d`)**

加拿起/放下音效時順手補的:

```gdscript
func test_sfx_files_present() -> void:
    var bv = load("res://render/battle_view.gd")
    for n in bv.SOUNDS:
        check(ResourceLoader.exists("res://assets/sfx/%s.wav" % n), ...)
```

commit message 裡寫得很直接:「`play_sound` 查無此名是靜默 return,沒有這個測試就會生出『叫得出來但沒聲音』的假機制」。

**存在性測試全綠,而兩個音效永遠不會響(血脈防線,2026-08-16)**

77 條測試全綠,其中包含上面那條掃過整張音效表的存在性測試。加了播放計數之後,跑一場完整的自動遊玩:

```
audio plays: { build: 24, fire_elf: 236, death_small: 118, coin: 14,
               wave_start: 1, leak: 7, death_big: 57, defeat: 1,
               tier_up: 6, fire_dwarf: 118 }
audio NEVER triggered this run: ui_click, hit, fire_human, fire_orc, victory
```

清單裡兩個是真 bug:

1. **`hit` 是 0** —— 事件型別定義了,但程式裡沒有任何地方發射它。做出來的是「程式叫得出來、玩家永遠聽不到」的假機制,而檔案一直都在。
2. **`victory` 是 0 而 `defeat` 是 1,那一場是贏的。** 結束音根本沒接上,唯一響過的結束音來自一次失敗的獎勵怪。贏了會安靜收場。

另外三個是預期的:自動遊玩沒有 UI 互動,而那個代理策略只蓋兩個種族。**價值在於每一項都要能解釋** —— 存在性測試永遠不會問這個問題。
