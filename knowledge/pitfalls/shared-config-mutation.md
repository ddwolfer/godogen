# 改寫載入來的設定,等於每一場都是不同的遊戲

> 「模擬層寫回它讀進來的那份設定,於是每一場都比前一場容易,而探針那張表看起來完全正常。」

資料驅動的模擬會把 JSON 讀成 Dictionary 然後到處傳。**那份 Dictionary 是共用的**,而「讀一個值」跟「讀完改回去」在程式碼裡差一個字元。

改回去之後,第二場戰鬥拿到的是被第一場改過的設定,第三場拿到的是被改兩次的。**每一場都在漂,而且是單調地漂** —— 探針跑三百場,平均的是三百個不同的遊戲,而輸出的表格不會有任何異狀,因為表格不會告訴你它平均的那些東西彼此不同。

模型推不出這條,因為 `grp["count"] = keep` 在任何語言裡都是合法的一行,而且它的意圖(「這一波少放一點」)完全正確 —— 錯的是它改的那個物件屬於誰。

## 規則

- **模擬層對載入來的資料一律唯讀。** 需要修改就先複製,而且是在建立新集合的時候複製,不是改完再複製。
- **深淺要看清楚。** `Array.duplicate()` 預設淺複製:陣列是新的,裡面的 Dictionary 還是同一批。改元素的欄位一樣會漏。
- **決定論測試要比對「第 N 場」對「第 1 場」,不是「第 2 場」對「第 1 場」。** 污染共用狀態的 bug 是每一場漂一點,而跑兩場的測試只證明第二場等於第一場 —— 那正好是這類 bug 最可能通過的形狀。

  ```gdscript
  var f1 = fingerprint(run(seed))
  var f2 = fingerprint(run(seed))       # 不夠
  run(other_seed)                        # 讓別的戰鬥動過共用資料
  var f3 = fingerprint(run(seed))
  check(f1 == f3, "一場戰鬥不受先前戰鬥影響")
  ```

- 探針每一趟開始前重新載入設定,不要重用上一趟的物件。

## 案例

**天敵波稀釋(血脈防線,2026-08-16)**

天敵波原本是單一屬性的洪水。加了一個「只保留 `purity` 比例、其餘換成填充敵人」的機制:

```gdscript
for g in groups:
    var grp: Dictionary = g
    grp["count"] = keep        # ← groups 來自 defs.waves,所有戰鬥共用
```

`purity` 是 0.75,所以第一場把該組敵人數量改成 75%,第二場在 75% 的基礎上再乘 0.75,第三場 42%……**每一場都比前一場容易**。

探針的表沒有任何異狀。抓到它的是那條「同一個種子必須跑出同一場」的測試,在下一次執行就紅了 —— 這是那條測試存在的全部理由,而它在專案裡躺了一整天沒抓到過任何東西。

修法是建立新的 list、複製要改的那幾個 Dictionary,而不是就地改。
