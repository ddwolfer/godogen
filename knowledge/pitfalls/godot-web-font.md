# 中文字型在 web 匯出會變豆腐方塊

> 「桌面完全正常,web 匯出後整個 UI 變成一排方框——因為瀏覽器沒有系統字型可抓。」

Godot 的 `SystemFont` 在桌面上會去抓作業系統的字型,跑得好好的。**web 匯出之後瀏覽器沒有系統字型可抓,整個 UI 變成方框。**

這條是 day-1 的事,因為它決定你的 UI 字型策略;但它通常在第一次 web 匯出(很晚)才爆。**任何非英文專案都適用。**

## 規則

- **打算出 web 就不要用 `SystemFont`**,一開始就嵌入字型檔。
- 中文字型完整版 15MB 以上,**必須子集化**(只留你用到的字)。
- **子集化的過濾邏輯會吃掉全形空格 U+3000 與全形標點。** 很多「濾掉空白字元」的實作用 `isspace()`,而 U+3000 會被判定為空白 —— 如果你拿它當排版用途,它會變成豆腐。子集字元集要明確把它們加回去。
- **可變字型的預設 weight 可能是 100**(細到看不清),而且執行期套 `FontVariation` 不一定生效。用 `fontTools.varLib.instancer` 把字重**烘進**子集,不要指望執行期調。
- 子集化後**要在 web 實際匯出看一次**,不是在桌面看。

## 案例

深坑公會用 U+3000 當按鈕內距,子集化時被 `isspace()` 濾掉,按鈕文字變成豆腐 —— 桌面版一切正常,只有瀏覽器裡看得到。

## 相關

[[godot-web-renderer]] 與 [[godot-web-audio-buses]] 是同一次 web 匯出會一起撞到的另外兩個問題。三條都屬於「桌面正常、瀏覽器才爆」那一族,而且都無聲無息,所以**要出 web 就早點做一次真的匯出**,在瀏覽器裡把畫面看過、把聲音量過。
