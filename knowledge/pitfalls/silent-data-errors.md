# 資料錯誤不會爆,它會變成靜默的空效果

> 「程式碼寫錯會爆給你看,資料寫錯只會安靜地少做一點事。」

資料驅動架構的賣點是「改資料不用改程式」,**代價正是失去編譯器**。JSON 是合法的 JSON、欄位型別也對、靜態檢查全過 —— 錯的是它跟**另一份資料**的關係,而那個沒有人在檢查。

失效方式不是崩潰,是**少做一點事**,而且那個差異會一路活進你的平衡數據裡。

## 規則

- **每個資料檔都要有 validator,而且要跑在測試套件裡,不是一次性腳本。** 一次性腳本只會在你想到的時候跑,而這類錯誤正是你想不到的時候發生的。
- **檢查的必須是交叉條件** —— 橫跨兩份資料的關係,因為任何一份單獨看都是合法的:
  - 地形不能蓋在虛空格或擋路格上
  - 駐防錨點必須是可走的格子
  - 波次的登陸點必須存在於這張地圖
  - 圖示/音效的檔名必須有對應檔案存在
- 簡寫語法(矩形、範圍、萬用字元)特別危險 —— 它把「四個格子」壓成一個運算式,而你看不見展開後撞到了什麼。

## 案例

深坑公會把地形寫成矩形簡寫 `[12,5,2,2]`(x, y, w, h),展開的四格裡有一格落在那張圖既有的 forest 擋路格上。

**沒有任何錯誤、沒有任何警告、遊戲照常跑。** 以為鋪了 4 格泥沼,實際生效 3 格。如果沒去查,這個差異會進到平衡探針的數字裡,然後拿一組錯的數字去調規則。

現在的做法是把它變成一條會紅的測試:

```gdscript
for name in ["map_battle", "map_canyon", "map_gauntlet", "map_crossing"]:
    var mm = SimMap.from_json("res://data/%s.json" % name)
    for t in mm.terrain:
        check(mm.walkable(t), "%s: 地形蓋在不可走的格子上 %s" % [name, t])
```
