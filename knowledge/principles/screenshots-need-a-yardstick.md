# 沒有判準的時候,截圖是拖延不是驗證

> 「我知道要改,但不知道改到什麼程度算好,所以只能一直微調然後看。」

「自己看畫面」是驗收裡最會抓到真問題的一層,但它有一個特定的失效模式:**當你不知道「好」長什麼樣的時候,它會退化成無限微調。**

徵狀很好認:連續好幾輪截圖,每輪都在動間距、圓角、色階這種尺度的東西,而且你說不出下一輪要達成什麼。這時候截圖已經不是在收集資訊了 —— 它在提供「有在做事」的感覺。

## 規則

- **開始改之前先取得外部判準。** 去查該領域的既有做法(UI、音訊、動畫都有成熟的判準),不要從自己的審美裡憑空生。判準可以是一句話,但必須能判對錯。
- **每一輪截圖前先寫下這輪要驗證什麼。** 寫不出來就代表你缺的是判準不是圖。
- **有判準之後通常一輪就收斂**,而不是漸近。如果還在漸近,判準沒選對。
- 這條不否定「自己看畫面」—— 它是那一層的前置條件。

## 案例

**元素牌堆,2026-08-15**

使用者對第一版 UI 的評語是「跟屎一樣」。我知道要重做,開始截圖調整:間距、圓角、面板底色、字級。連續幾輪,每輪都有變化,每輪都說不上變好。

打破它的是使用者一句話:「去網路上查一些遊戲 UI 相關的技能或教學吧」。查到的判準是**UI 要服務玩家當下的決策,不是把資訊攤平** —— 建造階段要看的是「我買得起什麼」,波次中要看的是「哪裡快守不住」,兩者不該是同一個版面。

有了這句話之後**一輪就收斂**,而且產出足夠穩定,直接變成了一個可重複使用的 skill。

整趟磁碟上有 609 張 PNG,但其中 600 張是同一支錄影的 movie frame。**真正打開來看的是 38 張**,而抓到問題的超過一半:圖示去背沒乾淨、元素顏色跟 UI 強調色撞色、深色底上的提示文字讀不出來 —— 全部是程式碼裡沒有痕跡、只有看圖才會發現的東西。

所以這一層的價值是真的。**空轉的不是截圖,是沒有判準的截圖。**
