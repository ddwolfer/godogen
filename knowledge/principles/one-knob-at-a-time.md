# 一次只轉一個旋鈕

> 「五個改動一起上,量測只會告訴你壞了,不會告訴你誰壞的。」

同時上五個削弱會把系統打崩,而且你**分不出是哪一個造成的**。量測只會告訴你「壞了」,不會告訴你「誰壞的」。

模型推不出這條,因為每一個改動單獨看都有充分的設計理由、而且都正確實作。錯的是「同時」。

## 規則

- 一次平衡調整只動一個變因,量測,再動下一個。
- 非得一起上不可時(例如它們在設計上互相依賴),**明確寫下預期效果**,量測結果偏離預期就整組退回,不要逐個猜。
- **改動之間會互相放大。** 兩個各自合理的規則相乘會產生第三個效果,單獨看任何一個都推不出來 —— 這是「一起上」比「分開上」危險的真正原因,不只是歸因困難。
- 大改動之後一定要跑平衡回歸,不要憑感覺。見 [[difficulty-tracks-player-power]]。
- **把這條掛在工具上,不要掛在文件上。** 讓平衡探針自己比對「這次的參數跟上次差幾個」,超過一個就印警告。這條規則要在「正想同時改兩個」的那一秒攔住你,而那一秒你正盯著數據,文件早就滾出注意力了。
- **連續 N 次單旋鈕掃描都回報「沒有效果」或「是懸崖」的時候,停止再掃第 N+1 個。** 那個模式本身就是訊號:你要的結果需要**幾個旋鈕同時到位**,而一次只轉一個永遠碰不到它,只會一次又一次給你看起來很有結論的負面結果。
- 這時候換第二檔:**把幾個 hold 在假設值、只掃剩下那一個**,而且 **hold 住的值要明列並印在輸出表頭**。「我順便也動了這個」正是掃描停止成為掃描的方式;讓工具強制它。
- 第二檔不是放棄紀律。單旋鈕掃描的產出仍然有用 —— 它告訴你那個旋鈕**不是**答案,而那是在縮小假設空間。

## 案例

**弓手削弱,6/6 → 0/6(深坑公會)**

弓手太強,一次上了五個削弱:

1. 箭改成投射物(會落空)
2. 行進間不能射擊
3. 射手不吃警戒迎擊
4. 費用從 3 漲到 4
5. 放敵方弓手進波表

防守勝率從 **6/6 掉到 0/6**,而且完全無法歸因 —— 五個變因同時動,探針只說「壞了」。花了很久逐個退回去才找出來。

**相乘出來的第三個效果**

「箭會落空」×「行進間不能射」= 射手在推進的路上**完全沒有輸出**。這是兩個各自合理的規則相乘出來的結果,單獨看任何一個都預測不到。

**七次單旋鈕掃描,七次撞牆(血脈防線,2026-08-16)**

目標是讓「專精一個種族」與「四族雜牌」的勝率拉開。每一次都只動一個,每一次的結果都是「全部 100%」或「全部 0%」:

| 旋鈕 | 結果 |
|---|---|
| 難度(每波血量成長) | 0.22 全贏,0.5 全死,中間沒有東西 |
| 種族傷害 | 22→32 有效,32→52 完全沒動(溢殺吃掉) |
| 同族成本成長 | 塔數 48→33,勝率一動也不動 |
| 金幣總量 | 1.0 全贏,0.72 只有雜牌活,0.55 全死 |
| 門檻加成強度 | 1→4.5 完全沒動,全部在天花板 |
| 門檻間距 | **假說方向反了** |
| 城堡血量 | 唯一產生中間值的:20→45→70 給 4%→36%→92% |

第八次改成 hold 住三個、只掃第四個,才第一次拿到梯度(雜牌 75%/25%/15%、專精 75%/65%/35%)。三個必要條件是**城堡血量(阻尼)+ 天敵波稀釋(讓專精活得下來)+ 收緊經濟(塔數不再壓倒一切)**,少任何一個都回到二元。

「門檻間距」那次是最有資訊量的一次:我以為拉開門檻會懲罰雜牌,實際上它**懲罰專精**(80%→12%)—— 門檻是專精的全部報酬,雜牌本來就沒在指望它。**單旋鈕掃描抓到的是因果方向錯了,那正是它該做的事。**
