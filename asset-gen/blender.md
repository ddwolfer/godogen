# Blender 程式化建模約定

模型用 `bpy` 純程式堆幾何體,不用生成式 3D。理由:同一個腳本跑一百次長得一模一樣,改一個參數就改造型;生成式的風格漂移會讓同一場戰鬥裡的單位看起來像不同遊戲。

參考規模:8 個兵種 + 建築,一份 234 行的腳本。

## 座標(最容易整批做錯的一條)

**Blender 是 Z-up、腳底放 `z=0`、正面朝 `-Y`。轉出 glTF 之後正面會變成 `+Z`。**

搞錯的症狀是整批模型躺著或背對鏡頭 —— 而且不會有任何錯誤。腳本開頭就把這條寫成註解,每次新增模型都對一次。

尺寸單位直接用遊戲的格子。把「一格多寬」定下來,所有模型照它算,匯入後就不用再縮放。

## 輪廓優先

每個單位 3–8 個幾何體,色塊、無貼圖。**瞇眼看要能分出是哪一種。**

- **細桿與平面在固定俯角下幾乎隱形。** 弓身、旗面、槍桿要加粗,而且要**斜向鏡頭**擺。
- **指向鏡頭的水平長物會透視縮成一根棍。** 平端的長槍認不出來,改成直立高桿。
- 剪影用**遊戲鏡頭**驗收,不是建模視角。建模視窗裡清楚的東西在俯視距離可能只剩一個點。

## 顏色

顏色表放在腳本頂端,並且**與渲染層的顏色常數是同一組 RGB**。兩邊各寫一份遲早會分岔,而分岔的症狀是「模型顏色跟 UI 圖例對不起來」,很難察覺。

腳本裡註明它對應渲染層的哪個常數。

## 匯出

```python
bpy.ops.export_scene.gltf(filepath=out, export_format="GLB")
```

每個模型一個檔,檔名等於單位 id。

**Blender 在 Python 出錯之後仍然退出 0**,會留下 0 byte 的檔案。所以匯出後一定要驗證檔案存在且非空 —— `blender_gen.py` 會做這件事,不要繞過它直接呼叫 Blender。

## 引擎端

GLB 的碰撞形狀用 AABB 推出的原始形狀(Box/Sphere/Capsule),絕不要對匯入的 mesh 用 trimesh 或 convex。細節見引擎指南。
